# Contributing

Thanks for helping. Issues and pull requests are welcome.

## Setup

Node 24 and pnpm (enable it with `corepack enable`).

```sh
pnpm install
pnpm dev
```

`pnpm dev` opens a browser profile with the extension loaded and reloads it on change. To try a production build in Brave, run `pnpm build` and load `out/chrome-mv3` with **Load unpacked**; after later builds, click the reload button on the extensions page.

## Before you open a pull request

```sh
pnpm verify
```

This runs Prettier, ESLint, `svelte-check`, the Vitest suite and a production build, the same as CI. Git hooks run ESLint and Prettier on staged files.

## Conventions

- **Commits** follow [Conventional Commits](https://www.conventionalcommits.org) (`feat:`, `fix:`, `docs:`, `chore:` …). commitlint checks this. Releases and `CHANGELOG.md` are generated by release-please from these messages, so never edit the changelog by hand.
- **Words** come from [CONTEXT.md](CONTEXT.md). Call things by the names defined there (Selection, Bubble, Provider, Prompt Profile …) in code, UI and docs.
- **Decisions** that are hard to reverse get a short ADR in [docs/adr](docs/adr). Read the existing ones before changing how keys are stored, how requests are made or which permissions are required.
- **Tests** live next to the code as `*.test.ts` and cover four seams: the translation client, Prompt Profiles, Language Pair decisions, and Provider privacy rules. UI changes are checked by hand in a Chromium browser.
- **Privacy is a feature.** No telemetry, no history, no automatic fallback from a Local Provider to the cloud, and nothing in the built-in model list that sends text to Google.

## Project layout

```
src/entrypoints/   background worker, content script (Bubble), Toolbar Popup, Settings
src/lib/           translation client, prompts, languages, providers, settings
public/            icons and UI strings (_locales/en, _locales/pl)
assets/logo.svg    source for the icons (pnpm icons)
docs/adr/          architecture decisions
```

## Releasing

Merging to `main` lets release-please open or update a release pull request. Merging that pull request tags the version, publishes a GitHub Release and attaches the extension zip.
